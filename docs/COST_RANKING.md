# 成本排序、范围差与贡献展开

检查点38补齐原PRD F05的排序与贡献查看。在项目中计算后，打开“成本排序与贡献”，可按模型/模块、实际物理设备或已有设备组、decode步骤选择范围，再按明确指标升序、降序或原始顺序展示。

这是已有分析结果的只读投影：不编辑方案，不重新推断模型成本，不改变inputHash、资产快照或项目修订。显示设置在页面重开后重置；完整结果JSON和原叶/执行成本CSV保持原来的内容与口径。数值引擎仍为`0.1.0-execution.12`，没有新增契约或内置资产修订。

## 排序与查找

- 可选择节点/模块理论耗时、逻辑读写、估计HBM、网络发送/接收/算法流量，以及下表的分精度工作指标。
- 计算类别按完整ComputeClass匹配：arithmetic、全部输入dtype及其category/format/bits、multiply/accumulate dtype、resource与resourceKey均参与，不按乘法位宽或相同format合并。
- 相同数值保持原始执行/结果顺序；不可用值在升序与降序中均排最后，保留原诊断及已知项小计。零与不可用分别显示，溢出不会显示为Infinity/NaN或生成百分比。
- 查找按节点、模块或设备ID匹配；先对全部匹配结果排序，再按每页40项展示。查找与翻页不会缩小占比分母。
- “实际执行项”保留普通叶节点、图内/方案通信及融合组，每次实际执行计一次。“模块汇总”按原模块范围列出各层容器；父子模块可重叠，因此不生成模块合计或占比。展开任一模块可查看其执行项构成。

## 有效、执行与范围差

同一ComputeClass内分别保留以下量：

| 指标 | 来源与含义 |
| --- | --- |
| 物理有效工作 U | 当前设备范围内局部成本的有效操作累计；复制执行可能使其大于模型一次有效工作 |
| 物理执行工作 E | 当前设备范围内包含作者声明padding、重算等因素的执行操作累计 |
| 模型一次有效工作 L | 已有model_useful结果或单卡原图有效工作；只在全部结果设备范围查看，不分摊到设备子集 |
| 物理执行 − 物理有效 | E−U，查看同一物理口径中的额外执行 |
| 物理有效 − 模型有效（范围差） | U−L，查看物理有效累计相对模型一次有效的差 |
| 物理执行 − 模型有效（范围差） | E−L，保留完整执行与模型一次有效之间的差 |

恒等式`E−L = (E−U) + (U−L)`有助于检查复制与局部额外执行：两卡完整复制GEMM的L=1024、U=E=2048，E−U=0而U−L=1024。局部padding手算例中，L=U=8、E=12，U−L=0而E−U=4。

选择整个decode序列时，U/E/L及差值都按实际步骤累计；L是各步模型有效工作的和，每步只计一次，不按复制设备重复增加。选择单步时只使用该步的原始结果和输入hash。

差值只比较相同ComputeClass，不自动推断原因，也不把精度转换、算法重排或作者不同方程的范围差都称作复制开销。局部与模型有效工作由不同方程声明时，范围差可以为负；原值保留，负值停用百分比。任一侧缺项时差值保持不可用。设备子集可查看明确的物理局部工作、流量和耗时，L及涉及L的范围差不会按设备数分摊。

## 贡献、融合与时间

执行项占比使用**当前选定范围的完整执行项合计**。即使搜索后只显示一行，其分母也仍是该范围完整合计。存在未知项、合计为零/溢出或负差值时不生成百分比；已知项小计仍保留。

融合成员不会与融合组一起计入执行项合计。展开融合行可查看数学成员ID，以及各实际decode步骤的数值；整个序列按每个子结果的真实融合情况重建构成。跨模块融合如果未声明物理成本分摊，该模块的相应执行贡献保持未知，不能把整个融合组塞进每个成员模块。模块原本独立可知的model_useful量仍可在模块汇总中查看。

耗时占比的分母是节点屏障持续时间累计，表示**执行耗时预算构成**，不是墙钟或关键路径贡献。界面并列保留引擎原范围耗时/跨度；多流重叠可使预算大于跨度。设备子集的普通节点取选定设备持续时间最大值，多流使用实际调度区间，包含已声明的资源效率/共享影响；通信沿用完整参与组的屏障耗时，不按成员数缩放。多流模块的设备子集时间取其已知执行区间首末跨度。

每行“展开构成”展示实际步骤、执行ID、结果设备范围、数学成员、当前值及原始组成值的数量/单位/basis；构成项也可单独排序。“公式、参数与原始来源”保留固定公式修订、原始表达式、参数来源及假设。范围共用依赖不代表每个公式都单独贡献当前指标；绑定值还可沿原结构与成本来源视图查看。长构成/来源列表有继续显示入口，不一次渲染完整模型的全部来源。

## 通信与设备组

网络发送、接收和算法流量分别查看。全组发送来自groupSendBytes，接收来自groupReceiveBytes；算法流量及设备子集来自明确的逐成员结果，不把发送和接收相加当成同一链路payload。没有逐设备HBM/逻辑访问分解的通信保持未知；网络payload不能替代HBM。

设备组是现有物理成员的选择范围。两个组名复用同一批成员不会增加卡数或重复成本。局部放置/成本缺失时保留未知，不从组总量按成员数平均拆分；某卡可知而另一卡不可知时，可以单独查看已知卡，但整组最大持续时间仍不可用。

## CSV与复现

“导出当前成本表 CSV”导出**全部查找匹配项**，采用当前排序，不限当前40项页面。列包含原inputHash、步骤、范围、设备ID、层级、指标/完整ComputeClass、单位、排序/查找、行ID/类型、原始数值、不可用说明和预算占比；另保留构成项对应的逐步输入hash集合。步骤索引在CSV中从0开始、页面从1开始。未知值/未定义占比为空字段并附原因，不写成0。

CSV的metric字段：`useful/executed/logical`分别为U/E/L，`delta/usefulGap/executedGap`分别为E−U/U−L/E−L；`seconds/read/write/hbm`为耗时/逻辑读/逻辑写/估计HBM，`send/receive/algorithm`为分开的网络量。`sourceStepInputHashesJson`保留构成项实际步骤的输入hash，整个序列的inputHash另列；不将一次步骤结果冒充整个序列。

这份CSV是派生显示表；完整输入和指标来源仍由项目快照及结果JSON承载，不能把该表当成实测记录或完整分析结果的替代。
