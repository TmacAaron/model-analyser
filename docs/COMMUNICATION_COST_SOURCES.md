# 通信步骤的实际来源

分析后，在「成本与覆盖来源」选择一条通信和所关心的指标。也可以从模型耗时的聚合明细打开实际通信步骤。选择「复核此通信的实际运算」可查看固定配置下的结果。若 Decode 有多个步骤，先选择其中一个实际步骤。

- **消息表达式。** 方案通信显示原公式与实际模型参数。图内通信保留固定资产、展开前的公式与实际调用的局部参数，并展示展开后的张量端点和物理设备组。
- **逐设备与组总量。** 统一消息用参与数量计算组总量。`send_recv` 各计算一个发送端与接收端。逐设备声明按原顺序累计发送和接收，各设备的算法系数只乘一次。非均匀时可从不可用的每成员指标打开逐设备明细。
- **链路与耗时。** 展示作者声明、图内角色绑定后的链路和配置覆盖后生效的链路。带宽与延迟模式取最大的发送算法流量除以带宽，再加启动轮数乘单轮延迟。固定和自定义耗时各自使用其实际声明。

报告按每页 20 台设备显示，导出包含固定输入与实际步骤上下文。用 `npm run verify:leaf-source -- <文件>` 检查公式、规则、端点和中间值。公式记录达到预算时，报告保留计算值并标注证据边界。

此处是通信求值器的理论网络耗时。多流执行区间在聚合来源或时间线查看。显存访问、临时空间和计算量分别由各自的成本声明决定。
