## 演示与恢复协议

在项目工作台展开“模型依赖升级 · 预览与恢复”，选择固定依赖的新修订或同类替代，先查看受影响父级，再应用保存。选择仅作用于当前方案模型树；不自动改动其他方案、硬件或独立预设。绑定/shape 不自动迁移，预览会检查新模型可展开；不兼容时需先修正资产。

`npm run reference:upgrade` 生成 `examples/upgrades`：原库六份资产、公式 r2、升级前/后完整项目、计划与独立数值摘要。原项目可直接导入计算。复现完整 UI 升级时，将 `library-r1` 的资产经 JSON 导入入库，再导入 `before-project.json`、发布 `formula-r2.json` 并选择新修订；保持示例固定 ID。人工硬件为 1000 ops/s、100 B/s，不代表真实设备性能。

预览只读，确认使用请求 ID 与计划 hash；应用重新检查项目版本、资产 head 和内容。父级按依赖顺序发布，最后切换项目。失败后可能留下合法已发布前缀，这不是跨文件原子事务。界面可查看未完成操作，重启后按同一请求恢复，响应丢失重试不会产生额外修订或回退较新 head。

尚未准备项目历史修订时可停止升级，已发布父级保留。项目历史或项目回执已经准备后必须恢复发布，不能通过停止留下阻塞下一次提交的不可变未来修订。新的编辑/草稿不会被删除：项目阶段尚未准备时，新草稿阻止切换；已准备的项目可以恢复完成，但界面保持更新的编辑内容，提示先导出恢复文件再合并。六个中断边界、过期预览、并发 head、请求 ID 冲突、损坏回执和较新草稿均有独立测试。
