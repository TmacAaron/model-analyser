# 实际调用的参数绑定来源

检查点70将普通资产绑定的实际执行记录接入模型画布的精确来源面板。选择实际叶指标并复核后，可以查看该算子及选中存储的参数上下文、实际值、候选覆盖顺序与编号依赖步骤。查看、分页和导出不修改模型配置。

## 来源身份与实际执行

绑定事件来自实际`bindParameters`执行，区分固定默认值、配置导入后的默认值、显式／工作负载绑定、已跳过的项目默认值、场景／节点覆盖及最终生效值。每条覆盖记录保留原始场景数组索引，排序后的候选顺序不替代其原始身份。

实例化过程按真实符号对象关联工作负载、资产和重复索引作用域。重复实例即使具有相同数值，仍保留不同的调用身份。绑定表达式读取父域的具体参数节点，不按相同参数名或数值猜测来源。存储使用其自身的实际参数域，未采集的外部域明确保留边界。

依赖图中的最终参数只连接实际生效候选。执行过但随后被覆盖的表达式另列为“被覆盖”，不会当成当前值的有效贡献。例如绑定表达式算出11后又由节点覆盖为11，这仍是两个候选，最终边连接后者。默认值未提供、项目默认值被跳过也分别记录。

## 有界证据与范围

普通参数观测最多128个作用域、2048条事件和16 MiB元数据；图最多256节点、256候选及256参数入口。达到预算后仍完成普通求值，显示部分证据。每页每类最多20项，切换指标立即回到新参数图的第一页。布尔／枚举参数保留类型，不伪装为数值符号。

这里展示的是实际调用和相关存储的参数上下文，参数列表不等于某个指标的贡献列表。固定资产默认值、导入后默认值和工作负载是本图输入根；配置导入转换过程以及量化、局部／分布式、融合、通信等其他参数域与变换链另计。此范围不等于一般F10的全部完成。

## 导出与复核

当前精确叶表达式和耗时报告导出为`schemaVersion: 2`，增加`parameterBindings`并明确`proofVersion`和证据预算。固定请求仍包含原指标、完整作用域、实际Decode步骤、引擎与输入hash。离线CLI重新执行完整固定输入，比较整个报告；数值自洽但候选状态、来源标签或覆盖索引被修改的文件会拒绝。

`npm run verify:leaf-source -- 文件.json`同时支持旧版`schemaVersion: 1`。检查点69的七份已签收旧格式文件在[独立归档](../_local/history/checkpoint70-preserved69-reports.json)中保留原SHA。

`npm run reference:binding-sources`生成[八份固定参考报告](../examples/binding-sources/manifest.json)，包含重复索引、同值覆盖、配置默认值、实际第三个Decode、类型参数和部分预算。`npm run acceptance:binding-sources`在原59步之前增加此参考检查，共60步。完整60步已在冻结源码上终端退出0；列明范围的签收状态见[检查点70结果](../_local/history/checkpoint70-result.json)。

该边界已由检查点71修复：`__proto__`、constructor和toString按真实声明的数值参数键进入快照；父域绑定及实际存储来源也经复核。当前808项单元与16项相关Chrome通过，16份既有固定参考文件SHA保持。原70的拒绝观察保留为历史复现，当前状态见[修复结果](../_local/history/checkpoint71-result.json)。
