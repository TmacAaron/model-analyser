## 1. 交付策略

先做一个能完整复算和自动保存的理论分析闭环，再增加特殊结构与多流，最后扩充资产和文件接入。

不以“支持全部模型、全部 trace、精确预测全部 kernel”为前置条件。新结构优先用可编辑资产与自定义公式解决，无法细化的开销允许显式覆盖。

第一批模型建议选一个具体 Qwen Dense/GQA 变体和一个具体 DeepSeek MoE/MLA 变体；实施时核对公开 config 和结构后固定资产版本。GLM 及家族其他型号按资产增量加入。不得把空目录或相似模板匹配视为已支持全系。

## 2. 最小架构

```text
本地界面
  ├─ 模型主画布、模块下钻与算子连线
  ├─ 配置视图切换、框选融合与侧边面板
  └─ 成本、显存、时间线、Roofline 与比较
          │
  共享类型、校验与受控公式
          │
  计算核心
  ├─ 模板实例化与形状推导
  ├─ 逻辑分片与通信节点
  ├─ 状态/生命周期与成本汇总
  └─ 耗时、指标、扫描与比较
          │
  本地文件读写层
  ├─ JSON/YAML 资产目录与修订
  └─ 项目、快照、草稿与测量记录
```

这是单应用结构，不拆微服务。统一使用 TypeScript 严格模式、Node.js 24 LTS、React + Vite 和 npm workspaces。Zod 4 是契约单一来源，类型从 Schema 推导，JSON Schema 自动导出。计算核心不依赖界面和具体推理框架，便于独立验证。必要时将扫描计算放入后台线程。

### 2.1 为什么保留本地文件层

用户要求新增定义自动成为持久预设，因此必须真正写入文件。仅使用浏览器内存、本地缓存或手动下载无法满足要求。

选择一个很薄的 Node.js 本地文件服务，统一处理文件读写、扫描、校验与冲突。资产目录可配置，默认只操作项目约定的数据目录。本轮不实现此服务。

### 2.2 建议目录（规划，不在本轮创建实现文件）

```text
assets/
  builtin/             随应用分发的基线
  user/                用户正式资产：按类型组织
  drafts/              未完成定义
  revisions/           被项目引用或需恢复的历史修订
projects/              项目、方案、资产快照与测量记录
```

每个资产是一份 JSON 或 YAML 权威文件。第一版默认生成 JSON；YAML 走同一加载和校验链。选择列表通过目录扫描构建，不手工维护总注册表。索引只作为可重建缓存。

## 3. 最小数据模型

| 对象 | 主要字段/关系 | 简化原则 |
| --- | --- | --- |
| Asset | ID、类型、名称、格式版本、修订、状态、参数、引用、正文 | 所有资产共用外壳 |
| Model/Module | 参数、重复层、子节点、连接、状态引用 | 容器可折叠，未知模块可用总成本公式 |
| Operator/Formula | shape、分精度工作量、读写量、临时空间、适用阶段 | 受控表达式，无任意脚本 |
| State | 创建者、使用者、更新、大小、共享域、分片 | KV、递归状态、索引等统一表达 |
| DeviceGroup | 设备集合或映射、组大小、硬件参数 | 对称情况用代表设备，不强制全量展开 |
| ParallelPlan | 作用范围、张量/状态分片、复制、通信、边界假设 | 不绑定框架合法性 |
| ExecutionPlan | 阶段、流、依赖、同步、资源共享假设 | 先串行，再做简单多流 |
| Scenario | 资产版本、工作负载、配置覆盖、测量 | 调参不创建大量资产 |
| Measurement | 目标、阶段、范围、时间、单位、次数、区间、来源 | 缺少口径则保留待确认 |
| Result | 分项成本、汇总、假设、版本摘要、错误 | 配置变化后失效重算 |

项目内保存可复算的资产快照。使用稳定节点 ID 对齐视图、测量和方案，避免用显示名称作为唯一匹配依据。

上表为概览，具体契约按技术规范执行：Tensor/Storage/State 分离，资产以 definition.kind 判别，草稿与正式定义分离，物理设备与逻辑组分离；schemaVersion、revision、engineVersion 分别管理格式、内容和算法版本。

## 4. 实施阶段与依赖

顺序为 P0 → P1 → P2 → P3 → P4 → P5 → P6。每个阶段结束时保留可演示、可复算的检查点。不得为后续高级能力持续扩大当前阶段。

| 阶段 | 交付 | 对应需求 | 完成门槛 |
| --- | --- | --- | --- |
| P0 数据契约与手算样例 | 统一类型、统计口径和代表案例 | 全部基础 | 字段足够且无框架依赖 |
| P1 自动持久化资产 | 文件读写、草稿、修订、引用、项目快照 | 资产体系 | 重启可恢复，旧项目不漂移 |
| P2 结构与公式 | 模板、config 草稿、编辑与依赖图 | F01–F02 | 自定义模型可创建与复用 |
| P3 静态成本闭环 | 并行、量化、显存、计算与流量 | F03–F05、F09 | 理论结果可手算核对 |
| P4 耗时与对比 | 串行耗时、Roofline、测量指标、方案对比 | F06–F08、F10 | V0.1 闭环可验收 |
| P5 复杂结构与多流 | 混合并行、特殊状态、复用、时间线 | F03–F06、F08 | V0.2 研究案例成立 |
| P6 扩充资产与导入 | 家族型号、有限 trace、外部转换 | F01、F07、接入需求 | V0.3 明确支持范围 |

### P0：固定口径和样例

工作项：

- 按技术规范落地 contracts 包：Zod Schema、推导类型、JSON Schema 导出、结构和语义诊断；不得重新选择一套契约或手写重复类型。
- 为资产、图/张量/存储/状态、设备组/分布、方案/执行计划、成本/结果和测量记录提供有效与非法样例。
- 将字段细则中的 C01–C06 拆为对应阶段的样例；P0 建立契约与手算输入，P1 验证持久化，后续阶段再验证成本与调度，不能在 P0 声称高级功能已完成。
- 固定 TypeScript 严格编译配置、包依赖方向、统一 SI 单位与数值边界。
- 确定单位、FLOPs、有效/执行工作量、通信发送/接收以及局部/全局汇总规则。
- 定义公式语言首批能力与错误处理，避免直接执行输入字符串代码。
- 准备小尺寸 GEMM、GQA、MoE、跨层共享状态、递归状态和双分支依赖的手算样例。
- 确定首批两个具体模型及资料来源。明确预设覆盖范围和未细化部分。

退出条件：完成技术规范第 14 节中本阶段的 Schema、样例、单位和独立计算约束验证；样例可用纸笔或独立计算核对；新增同类算子仅需元数据。此阶段不建设通用编译器、插件系统或任意 Python 解析器。

### P1：先完成资产自动保存

工作项：

- 建立统一资产 schema 与 JSON/YAML 解析、扫描、字段校验。
- 支持内置基线、用户资产、草稿和必要历史修订。
- 实现新增即草稿、短暂停顿自动保存、有效定义进入选择列表。
- 写入采用临时文件替换，成功确认后才显示已保存。
- 实现写入失败保留编辑内容、重试与恢复导出。
- 创建/编辑公式、模块等定义后自动入库，不增加另一个保存预设步骤。
- 实现内置资产修改自动生成用户副本、归档、复制和冲突处理。
- 项目保存资产版本与完整快照；显式更新引用才使结果失效。
- 参数覆盖自动保存在项目；不为每次调参生成独立定义。

演示：新增公式 → 新增模块引用公式 → 新建模型 → 重启 → 重新选择模型 → 修改公式生成新修订 → 旧项目仍使用旧修订 → 显式更新后变化。

退出条件：完成 PRD 6.6 的持久化验收，包括失败路径。自动保存不得留到最后补做。

### P2：结构、依赖和公式编辑

工作项：

- 实现可重复、可混合的模块模板和模型实例化。
- 支持配置表增删节点、修改参数与依赖，使用稳定节点 ID。
- 提供层级树与按需展开的依赖图；区分结构包含关系、数据依赖、同步与状态引用。
- 分开表达 prefill/decode；递归状态跨步更新不进入单步数据环。
- 实现受控公式求值、shape 传递、单位提示和错误定位。
- config 按已知字段和模板匹配创建草稿，显示未识别与缺失字段。
- 录入两个代表模型的结构资产；提供自定义总成本模块作为扩展降级入口。

退出条件：模板修改自动持久化；模型可展开到算子并解释公式；结构未知部分仍能用用户定义继续分析。

### P3：静态成本、并行、量化与显存

工作项：

- 实现逻辑张量分片、复制与设备映射；常见预设生成必要通信节点。
- 高级配置支持模块范围、分片轴和手动通信，不要求自动推导所有边界。
- 计算局部与整体 FLOPs、理论读写、通信 payload；分开有效与额外执行成本。
- 实现分位宽的权重、激活、状态和通信成本，计入 scale、block/group 和辅助数据。
- 将存储位宽与计算精度分开；按运算类型保存成本。
- 实现静态执行顺序下的基本生命周期、共享状态去重及临时空间。
- 允许固定值、公式和张量推导的 workspace/graph/通信 buffer 等开销。
- 输出各设备组显存分解与限制条件，支持普通状态模型的容量求解。
- 增加维度、归约、缺失通信和引用合法性提示。

退出条件：GQA 的 TP/复制、MoE 的专家驻留/激活成本、W4A8 的辅助数据及 KV 容量都有独立参考案例。所有覆盖值可查看来源，不重复计数。

### P4：理论耗时、Roofline 和测量比较

工作项：

- 建立硬件资产字段，提供可编辑算力/带宽/通信参数。
- 首批核对设备信息后填充，公开资料不明确的值留空或标注假设；不阻塞手工创建硬件。
- 使用节点公式与效率计算串行基线；区分理想下界和用户有效参数下的估算。
- 通信使用明确 payload 口径、延迟及算法系数；先不拟合复杂拓扑拥塞。
- 支持 batch/长度扫描、不同精度 Roofline 与方案交叉点。
- 支持手工测量与统一 CSV/JSON 导入，按目标、范围和次数校验。
- 计算匹配粒度的 MFU/MBU；理论 bytes 标注估算 MBU。
- 实现方案复制、结果表与差异展示、项目导入导出。

退出条件：V0.1 全流程可演示；用户可独立添加资产、选择并行/量化、计算并对照手工时间。无需任何采集端。

### P5：研究能力与特殊机制

工作项：

- 扩展模块级 SP/TP/EP、attention 前后 AllToAll 和不同范围设备组复用。
- 支持流内顺序、跨流依赖/同步，输出简单多流估算时间线。
- 基于执行时间线重算张量存活峰值，展示掩盖收益与额外 buffer。
- 提供共享资源折减/带宽共享的简单配置；未建模争用时显式标为理想结果。
- 录入混合 attention、滑窗、DSA/indexer、KDA/递归状态及序列压缩预设。
- 录入跨层 KV、indexer 状态、索引结果等独立共享关系。
- 选择 DeepSeek V4.1 Flash 的相关结构片段作为复用案例，逐项核对公开定义；不把所有复用简化为一个比例。
- 容量求解支持分段/取整公式和递归状态；不单调时使用有界扫描或仅显示指定点。

退出条件：三个研究案例可复现：Ulysses 风格布局交换、MoE 混合并行、多流与状态复用。结果能解释每项节省或增加的成本。

### P6：扩充预设与文件适配

工作项：

- 按明确型号和变体扩充 Qwen、DeepSeek、GLM 资产目录，复用公式和模块。
- 补充硬件、通信、融合和量化的可编辑预设与来源说明。
- 先选择少量真实文件样本，再决定支持的 Chrome Trace/算子 CSV 字段和规模。
- 实现事件导入、范围选择、匹配规则、未匹配/歧义清单与确认应用。
- 发布统一转换格式说明和样例，让外部 Agent/脚本生成可导入记录。
- 可以导出模型/节点摘要供外部工具映射，不建设在线 Agent 编排。

退出条件：支持范围按实际样本列明；未知文件可走统一表格或外部转换路径。自动解析不能覆盖的范围不生成伪实测指标。

## 5. 必须验证的案例

| 案例 | 检查点 |
| --- | --- |
| 小尺寸 GEMM | 2MKN、输入输出 bytes、参数变化和单位换算 |
| GQA 与 TP | KV head 分片/复制、权重归约、局部与整体成本 |
| MoE | 总专家驻留、top-k 工作量、batch 触及专家及 dispatch/combine |
| 量化 | 权重 bit packing、ceil、scale/zero point、内部计算精度 |
| 混合持久状态 | 普通 KV 增长、滑窗封顶、递归状态、共享对象去重 |
| 并行组复用 | 使用同一批设备不扩大物理卡数，复制成本仍正确 |
| 串行/多流 | 流内顺序、跨流依赖、汇合等待和资源假设 |
| 多流显存 | 两分支并发时张量同时存活，峰值可高于串行 |
| 复用与流量 | 同一份状态仅一份显存，多次读取仍产生流量 |
| 融合 | FLOPs 不重复，只有声明的中间读写与开销改变 |
| MFU/MBU | 设备、阶段、时间和 bytes 口径一致；混合精度不混分母 |
| Roofline 扫描 | 无拐点、多拐点及取整边界正确显示 |
| 持久化 | 草稿恢复、有效修订、失败重试、导入冲突和归档引用 |
| 项目复现 | 资产库更新后旧项目不漂移；空资产环境可由快照复算 |

验证优先使用手算、小规模独立计算和已明确的数学关系。对可逆界面微调不编写形式化测试；对公式、汇总、持久化和引用等正确性风险建立自动回归。

## 6. 控制复杂度的具体规则

| 遇到的问题 | 首选处理 | 暂不采用 |
| --- | --- | --- |
| 新模型解析不出来 | 从模板生成草稿，手动补结构 | 任意源码自动理解系统 |
| 特殊模块难以展开 | 用户成本公式与状态定义 | 为单个模型扩展整套执行引擎 |
| 通信边界过于复杂 | 手动通信节点＋缺项提示 | 自动求最优布局重排 |
| Workspace/graph 不确定 | 固定值或用户公式 | kernel 级分配器模拟 |
| 多流争用难精确模拟 | 理想重叠＋简单共享/折减假设 | 硬件周期级仿真 |
| 文件格式差异大 | 统一测量表＋外部转换 | 全格式 trace 通吃 |
| 硬件资料不完整 | 参数留空/假设、允许覆盖 | 编造默认值或强制现场采集 |
| 扩展预设越来越多 | 数据文件扫描、公共模板和引用 | 引入数据库或在线资产市场 |

## 7. 风险与应对

- **自动保存导致资产污染**：区分定义编辑和方案覆盖；草稿不进入正式选择列表；内置修改创建副本。
- **更新导致历史结果变化**：引用修订＋项目快照；更新显式触发重算。
- **共享状态省错成本**：存储引用与计算依赖分别记录；重复读取不能因共享而免费。
- **理论结果被误读为真实性能**：每个结果注明公式、效率、重叠和流量假设，实测单独保存。
- **复杂参数增加学习成本**：默认模板与折叠面板，选中节点再展开高级字段。
- **元数据能力被过度承诺**：保证已有表达能力的组合可纯数据扩展；新语义仍需有限核心升级。
- **家族支持工作量失控**：按具体结构覆盖清单验收，不用“全系”作为首版门槛。

## 8. 工作量与进度管理

当前不承诺日历工期：界面编辑深度、首批资产细度和文件样本尚未通过实现验证。P0 结束后再按实际字段与案例拆分工作项，P1/P2 建立开发基线后估算剩余工作。

复杂度判断：

- 较低：硬件参数表、方案参数、标准表格导入和结果导出。
- 中等：模板/config 草稿、受控公式、资产自动保存/修订、静态成本、Roofline。
- 较高：混合并行边界、跨层共享状态、多流资源争用、非标准 trace 映射。

如需压缩首版，优先减少具体模型数量、图编辑交互和 trace 支持范围；不能删减自动持久化、数据依赖、单位口径和结果来源。

## 9. 每阶段交付记录

每个阶段结束记录：

- 已完成的需求 ID 与可演示路径。
- 新增/更新的资产及来源、版本和覆盖范围。
- 已执行的关键验证与结果。
- 保留的假设、降级和已知限制。
- 下一阶段依赖与明确未实现项。

只有所有退出条件成立后才能标记阶段完成。文档中的规划、占位目录和未核对预设不得记为已交付功能。

## 10. 实施启动清单

后续开始实现时依次处理：

1. 将 PRD、计划和技术规范共同作为基线，后续变更同步更新；实现阶段执行已定技术选型。
2. 固定首批代表模型和小尺寸手算案例。
3. 完成 P0 的最小资产、图、状态、测量和结果契约。
4. 先验证自动持久化与项目复现，再增加计算页面。
5. 按阶段推进，V0.1 验收后再进入高级多流与特殊机制。

本轮止于文档，不执行上述启动步骤。
