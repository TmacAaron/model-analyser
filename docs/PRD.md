## 1. 产品定位

Model Analyser 是面向大模型推理的结构学习、理论性能分析和并行方案评估工具。

用户从预设模型开始，或通过 config 创建草稿，编辑模型计算逻辑、算子、公式、并行方式、量化与硬件参数，查看结构与数据依赖，以及由这些假设推导出的显存、计算量、搬运量、通信量、耗时和 Roofline。用户也可输入实际耗时，与理论结果对比。

产品主要服务部署前研究、框架适配优化评估和学习展示。vLLM、vLLM-Ascend 等实现用于整理参考预设，不构成模型表达或并行方案的限制。

### 1.1 产品原则

1. 预设优先、用户可改，不追求理解任意模型代码。
2. 理论分析优先，无法确定的量使用明确默认值，并允许覆盖。
3. 结构、数据依赖和成本口径统一，避免各视图分别维护计算逻辑。
4. 用户新增模型、模块、算子、公式等定义后，自动持久化为可复用资产。
5. 资产由 JSON/YAML 元数据描述；扩展已有能力组合时，无需改产品代码。
6. 复杂机制允许先用自定义公式或模块级数值表达，后续再细化。
7. 结果必须能解释来源、公式、参数与假设；估算值和测量值明确区分。

### 1.2 不在当前范围

- 训练、反向传播与优化器状态分析。
- 自动解析并执行任意 Transformers Python 代码。
- 自动还原编译器、kernel、指令、tiling 或物理存储布局。
- 精确模拟硬件调度、缓存命中和真实通信拥塞。
- 维护框架版本兼容矩阵、生成部署命令或直接修改推理框架。
- 采集端、在线服务监控、远程执行集群。
- 量化精度评测和精度损失预测。
- 内置完整 Agent 编排系统、多用户协作与云端资产市场。

## 2. 用户与关键场景

| 用户/场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 学习模型结构 | 展开一个模型层，选中 attention 或 MoE | 看到公式、张量形状、依赖关系及成本 |
| 研究并行适配 | 将 attention 与 MoE 配置为不同切分方式 | 看到权重/状态分布、必要通信和成本变化 |
| 研究多流掩盖 | 将无数据依赖的分支分配到不同流 | 看到同步点、理论时间线和掩盖假设 |
| 规划显存 | 调整量化、并发、序列长度、workspace 和 graph 开销 | 得到各设备组的显存分解和容量限制 |
| 对比优化方案 | 复制方案，修改一个并行或融合策略 | 看到显存、流量、耗时及 Roofline 的差异 |
| 扩展新模型 | 从 config 草稿补充特殊模块和公式 | 新定义自动进入资产库，下次可直接选择 |
| 对照实际性能 | 选择模块，录入对应区间的实际耗时 | 得到相同口径下的 MFU/MBU 和理论差距 |

## 3. 核心工作流程

1. 选择模型预设直接打开结构画布，或上传 config 匹配相近模板；不要求先创建空项目。
2. 确认结构、阶段、参数及缺项；按需修改模块、算子和公式。
3. 配置工作负载、硬件、并行、量化、额外显存和效率假设。
4. 从画布选择模块／算子，查看派生的成本、显存、时间线和 Roofline；在同一模型下切换、复制与对比配置。
5. 框选算子查看推荐融合，指定融合或修改连线；切换并行、量化等配置并比较收益与代价。
6. 可选：录入测量数据，或导入外部转换后的记录。

新定义在以上编辑过程中自动保存，不要求另外执行“保存为预设”。项目参数覆盖与资产定义编辑必须在界面上明确区分。

## 4. 产品信息组织

主工作区以模型结构画布为中心：

- **模型与配置**：选择模型即打开画布；同一模型下切换、复制和对照不同工作负载、并行、量化与融合配置。底层项目／方案文件不构成用户必须先创建的一级对象。
- **主画布**：模块连线与算子级计算流程；点击下钻、悬浮计算摘要、拖拽节点与连线、平移缩放、框选多选及融合推荐。
- **配置面板**：选中节点的公式、精度、并行、设备组、流、开销与测量数据。
- **分析结果**：成本表、显存、时间线、Roofline、方案比较。
- **辅助算法库**：按模块／算子及其算法组织公式、单位与来源；定义编辑、复制、归档和导入导出保留在辅助入口，资产库不作为一级大页面。

默认展示模型画布，配置与算法详情按选择在侧边展开。节点拖拽、连线编辑、缩放和平移为明确需求；表单和高级定义用于补充不能从图操作唯一推断的方程与语义。布局和计算改动分别保存、校验。

## 5. 功能需求

### F01 模型预设、config 草稿与结构编辑

- 界面按 Qwen、DeepSeek、GLM 等家族组织，内部按结构模板复用。
- 预设应明确具体模型/变体及已覆盖的结构，不能仅凭品牌宣称全系适配。
- 型号目录按家族列出明确发布的型号。目标包含 DeepSeek-V3、DeepSeek-R1、DeepSeek-V4-Flash、DeepSeek-V4.1-Flash、GLM-5.2、Kimi-K3、Qwen3.5-397B-A17B 和 Qwen3.8-27B。每个可计算预设需固定对应型号的配置、结构来源和建模范围。[目标型号来源](MODEL_REFERENCES.md#目标型号来源)
- 支持重复层、不同层类型混合、分支、残差、共享权重和跨层状态引用。
- 支持模型级、层级、模块级和算子级展开；重复层可折叠，特殊层可独立配置。
- config 导入识别层数、维度、head、专家数及可识别量化字段；缺项逐项标注。
- 未知模型生成草稿，用户选择最接近模板并修正；不猜测缺失语义为确定事实。
- 支持增删替换模块、修改连接、添加自定义模块及参数。
- 自定义模块可先直接描述输出形状、参数量、FLOPs、流量和状态公式，无需展开内部步骤。

验收：已支持模型可实例化；新模型草稿能修改、关闭后恢复，并在发布有效定义后出现在模型库。

### F02 公式、逻辑算子与依赖图

- 预设覆盖 Linear/GEMM、Norm、RoPE、激活、attention、router、专家计算及常见通信等类别，按阶段逐步增加具体模板。
- 公式与算子可分别复用；公式支持参数说明、单位、适用条件和引用来源。
- 显示输入输出 shape、存储位宽、内部计算精度及各项成本。
- 依赖图包含数据依赖、控制/同步依赖；持久状态另记读取、更新和引用关系。
- 模块内部先展示 Attention、RMSNorm、RoPE 等逻辑算子。展开后才展示具体计算方式。激活的融合组在父层显示为单一节点，进入后查看原成员和内部张量边。残差与 MoE 路由、共享专家分支保留实际分流和汇合关系。
- Prefill 和 decode 可有不同节点、公式和依赖。跨步递归状态按状态更新表达，不直接形成单步 DAG 的环。
- 支持融合组：保留组内数学步骤，配置中间张量是否物化、额外开销和效率。
- 成本汇总只计算当前生效的展开方式，避免父模块与子算子、融合组与原算子重复计数。
- 推荐算子和融合方案仅作为候选，用户决定采用何种配置。

验收：选中模块可追踪到公式和依赖；修改形状参数后所有关联结果更新；融合开关不会重复计算 FLOPs。

### F03 并行预设与高级混合并行

- 支持 TP、DP、EP、SP、PCP、DCP、PP 等名称的快捷预设，每个预设必须说明其实际分片和通信语义。
- 主入口按计算范围填写并行度，包括 Attention 的 TP／DP、MoE 的 EP／TP 和上下文并行的 PCP 等。先预览逻辑分片与通信，再按需要关联物理硬件。高级设备与拓扑编辑仍可单独进入。
- 用户指定设备组与物理设备复用关系，不能将所有并行度机械相乘作为卡数。
- 高级模式按层/模块/算子及 prefill/decode 选择作用范围。
- 权重、激活和持久状态可分别沿 token、head、hidden、expert、vocab 等维度切分或复制。
- 支持用户显式插入 AllReduce、AllGather、ReduceScatter、AllToAll 和点对点传输，并配置 payload、组规模、位宽和算法系数。
- 初期只为常见预设自动插入通信；复杂自定义边界由用户补充，系统提示待确认处。
- 支持 attention 内 head 分片、外部序列分片，以及 MoE 的 SP/EP/TP 组合。
- 支持不同模块复用同一批设备，或使用独立设备组。
- 检查整除、分片对应、归约完整性、边界张量兼容性、设备映射一致性；不以框架支持情况阻止方案。
- 不均匀切分可通过显式分片尺寸/设备组覆盖值表达；不做自动最优分片搜索。

验收：可表达“SP → AllToAll → head 分片 attention → AllToAll → SP”，以及 MoE 中 token 分片、EP、expert 内 TP 的组合；能标出缺少通信的边界。

### F04 显存、持久状态与 KV 容量

容量首页在当前模型、并行、量化和显存限制下展示每 token 的 KV 开销和可容纳的 KV token 预算，并说明按单请求、整批还是逐卡统计。模型上下文上限已知时，主卡片显示同时满足显存、模型上限和分片对齐的每请求长度。压缩、对齐或分片造成的非固定开销应显示其实际口径。任意参数穷举保留为高级分析入口。

- 按设备或等价设备组展示权重、量化辅助数据、持久状态、激活、workspace、通信 buffer、graph、运行时保留和额外余量。
- 支持固定字节数、参数公式和张量推导三种开销输入方式。
- 默认依据执行计划和张量最后一次使用估算生命周期；多流下考虑同时存活。用户可覆盖模块或设备组峰值，并标明覆盖范围。
- 共享 buffer 显式使用同一存储引用，避免重复计数；不同设备的物理副本分别计算。
- 第一版重点分析稳态推理峰值；加载/转换峰值可用额外开销描述，暂不自动模拟加载流程。
- 容量分析固定并发求最大长度，或固定长度求最大并发；显示限制设备组、取整和假设。
- 若容量公式不满足已知单调条件或未给出搜索范围，提示无法可靠求极值，允许输出用户指定点的显存或区间扫描。
- 对混合状态模型同时展示 KV 与其他持久状态，不将全部状态换算为通用 KV token 数。

#### 注意力与状态表达

| 机制 | 最低表达要求 |
| --- | --- |
| 普通 MHA/GQA/MQA | 实际 KV head、K/V 维度、位宽和分片/复制 |
| MLA | latent、位置相关状态及实现假设，不套用普通 KV 公式 |
| 滑窗 | 有效窗口、保留策略和随长度增长的上限 |
| 稀疏 attention/DSA | 主状态、indexer 状态、选择开销、访问条目数；稀疏读取不自动代表少存状态 |
| 序列压缩 | 压缩率、ceil/边界条目、压缩计算和额外窗口状态 |
| 线性/递归 attention、KDA | 有限递归状态、相关短历史状态、prefill/decode 的不同计算公式 |
| 混合 attention | 各层使用独立机制后汇总 |
| 跨层复用 | KV、indexer 状态、索引结果或其他中间量的独立创建与引用 |

状态对象记录创建者、使用者、更新时机、shape/大小公式、所属设备和共享范围。共享范围必须区分跨层、单请求、跨请求及设备副本；不能仅凭同名跨请求去重。

复用只消除被明确复用的存储或计算：共享 KV 不代表后续读取免费；复用 Top-K 不代表省去 attention。DeepSeek V4.1 Flash 等特殊结构通过具体预设表达，不添加品牌专用的通用计算分支。

验收：普通、混合和递归状态能分别计量；同一状态跨层引用不重复占用驻留显存，其多次读取仍按公式计入流量。

### F05 计算量、搬运量与通信量

- 在算子、模块、层、模型及设备组粒度汇总。
- 区分有效模型工作量与包含复制、padding、重算的执行工作量。
- FLOPs 按约定采用一次乘加计 2 次运算；整数运算与不同精度分别统计，避免混用。
- 搬运量默认是理论逻辑读写量；可配置重读/复用系数和节点级覆盖值，不声称是实测 HBM bytes。
- 通信明确每 rank 发送/接收、组内汇总与链路开销口径；默认避免将发送与接收相加后当成同一链路的 payload。
- MoE 分开计算总驻留专家、激活专家、batch 触及专家和负载不均衡，未知时提供可编辑假设。
- 提供按成本排序、展开贡献和公式解释。

验收：同一成本可由叶节点汇总到模型，不重复计数；复制和 padding 的额外成本能单独查看。

### F06 理论耗时、多流与掩盖

- 硬件预设包含显存、不同精度计算能力、内存带宽、通信带宽与启动延迟，所有值可覆盖。
- 可内置 H20、910B2/B3、950PR/DT 等设备条目；经核对的数据附来源，未知项留空或标为假设，不填伪精确值。
- 默认提供设备内/设备间两级通信参数；自定义链路和高级搬运通路按需展开。
- 支持算子计算效率、带宽效率、固定启动开销及直接耗时覆盖。
- 各节点计算/搬运关系由模板定义；默认可使用理想重叠下界，明确标注。通信通常作为独立节点，融合通信须单独声明。
- 默认串行执行；高级模式支持设备组、流内顺序、依赖及同步点的简单确定性调度。
- 展示串行基线、指定多流后的估算与节省时间；不同执行方案分别重算显存峰值。
- 对共享 HBM/计算资源的并发，提供简单共享模型或效率折减。未设置争用时，结果标注为理想重叠估算。
- 不实现指令级模拟或自动寻找最佳流划分。

验收：存在依赖的节点不能提前执行；同一流保持顺序；独立分支可重叠，汇合处等待；更改效率可解释地影响耗时。

### F07 实际耗时、MFU 与 MBU

- 用户选择算子、模块、模型或方案，录入时间、次数、阶段、设备范围和统计区间。
- 单次耗时、平均耗时、累计耗时、区间跨度分别记录；统一换算后再计算指标。
- 使用匹配范围的有效 FLOPs 和设备峰值计算 MFU；执行工作量利用率另列，避免混淆。
- MBU 明确使用理论 bytes 还是测量 bytes；缺少测量 bytes 时标为估算 MBU。
- 混合运算精度分项展示，不把 INT TOPS 与浮点 TFLOPS 直接相加；不定义含糊的混合精度 MFU。
- 模块跨度与子算子累计时间分开处理，重叠区间不能重复累加成端到端耗时。
- 只有模型总时间时，不自动生成子模块实测时间。不能独立测量的融合内部步骤可保留空白。
- 超过 100% 时提示检查统计口径、单位和峰值配置，不强行裁剪。

验收：手工录入即可使用，无需 trace；没有对应粒度的测量时，界面不会显示伪造的细粒度实测指标。

### F08 Roofline 与参数扫描

- 按算子、模块和模型显示算术强度及性能点；聚合图提示可能掩盖局部瓶颈。
- 区分硬件峰值屋顶与用户有效能力屋顶。
- 扫描 batch、prefill 长度、decode 上下文等变量，其余变量固定并显示。
- 计算满足当前公式的拐点和方案交叉点；无交点、多个交点或超出范围时如实显示。
- 当前模型、并行、量化、效率或工作负载改变后重算。
- 通信限制先以成本占比和时间线展示，不强行并入单一 HBM Roofline。

验收：不预设每个模型都有唯一序列长度拐点；扫描结果可追溯到公式和参数。

### F09 量化

- 分别配置权重、激活、持久状态和通信的存储/传输位宽。
- 配置 scale、zero point、block/group size、辅助数据位宽和元素取整规则。
- 内部计算精度、累加精度与输入输出存储精度独立；未设置时按模板或输入输出精度推断，并标明默认来源。
- 支持模块内部按步骤区分 8/16 bit 等混合计算，不需要对应真实 kernel。
- 量化/反量化可作为独立节点或融合组内成本，不能重复添加。
- 支持 Ascend 量化描述文件等输入对已知模块的字段映射；未知项保留为待确认。
- 量化变化影响显存、计算分类、搬运、通信与理论耗时，不输出精度质量结论。

验收：W4A4、W4A8 等方案可计入辅助数据；attention 的 8 bit 存储和内部 16 bit 计算可以同时表达。

### F10 方案比较与学习解释

- 支持复制、命名、修改和保存方案，比较显存、容量、FLOPs、流量、通信与耗时。
- 展示结果变化对应的模块与参数变化，不要求自动生成复杂优化建议。
- 点击指标可查看公式、参数值、单位、覆盖来源及相关假设。
- 用户可导出项目和结果表，方便复查与分享。

## 6. 资产体系与自动持久化

### 6.1 资产类型

至少包含模型、模块、算子、公式、并行预设、量化预设和硬件预设。通信规则可作为算子/并行资产的组成部分，避免过早拆分更多类型。

所有类型采用统一资产外壳：稳定 ID、类型、名称、描述、标签、格式版本、内容修订号、状态、参数定义、依赖引用、定义正文及可选来源。模型家族是分类字段，不是代码分支。

### 6.2 JSON/YAML 规则

- JSON 和 YAML 解析为同一种内部数据结构，执行相同校验，不维护两套语义。
- 应用默认写入 JSON；导入 YAML 可保留原格式，也可转为 JSON，由导入设置决定。
- 一个资产只有一个权威定义文件，不能同时维护含义不明的 JSON/YAML 副本。
- 扩展资产采用元数据与受控公式，不允许依赖任意可执行脚本才能加载。
- 新组合、参数、公式、共享关系和成本定义可纯数据扩展；全新表达语义若超出已有公式/图能力，才需要扩展产品代码。
- 预设需要维护修订和来源，但无需绑定某个推理框架版本。

### 6.3 自动保存行为

1. 新增定义即创建稳定 ID，并自动保存草稿。
2. 编辑短暂停顿后保存；界面显示“保存中 / 已保存 / 保存失败”。建议默认防抖 800 ms，可在实现时根据体验微调。
3. 校验通过后更新正式修订并出现在资产选择列表；缺少必填项的内容保留草稿，不能参与正式计算。
4. 编辑已有资产时保留上一份有效修订；未完成编辑不破坏正在使用的版本。
5. 正式修订按语义变化生成，连续输入合并提交；无需为每个按键生成版本。
6. 成功提示必须在文件写入确认后出现。写入失败时保留编辑内容和待写状态，提供重试和导出恢复文件。
7. 使用临时文件加替换方式避免半写文件；保存错误不得静默丢弃。
8. 应用启动时扫描目录，无需手工登记资产列表。批量导入或重新扫描后，新定义自动可选。

### 6.4 项目参数与资产编辑边界

- batch、当前序列长度、方案中的并行度等普通参数修改，自动保存到项目，不为每次调参创建新资产。
- 使用“新增模型/模块/算子/公式”等定义入口时，定义自动进入资产库。
- “编辑资产”修改可复用定义；“当前方案覆盖”只改变方案，界面必须明确区分。
- 内置资产采用只读基线；修改时自动生成用户副本并切换当前编辑引用，避免覆盖后无法恢复。
- 用户资产支持继续编辑、复制、导出和归档。被引用资产默认归档而非破坏性删除。

### 6.5 引用与可复现性

- 资产引用包含稳定 ID 和修订号。
- 项目保存所用资产的完整快照及版本引用，脱离原资产目录仍可重新打开。
- 资产更新不静默改变旧项目。用户显式更新引用后，相关分析结果失效并重新计算。
- 配置、公式和资产版本相同，应得到相同理论结果。
- 导入同 ID 同修订但内容不同的资产时视为冲突，要求保留副本或明确选择，不能无提示覆盖。
- 检查缺失引用、重复 ID、无效公式与依赖环。普通数据依赖环禁止；递归状态使用专用读写关系表达。

### 6.6 最低持久化验收

- 新建一个模块及其公式，关闭应用后重开，两者仍在资产库且引用有效。
- 新建模型引用该模块，导出项目到另一个空资产目录仍可打开并计算。
- 修改模块生成新修订，旧项目仍保留旧结果；显式更新后才变化。
- 未完成公式自动恢复为草稿，不覆盖上一有效公式。
- 模拟写入失败时不会显示“已保存”，可恢复编辑内容。
- 手动添加一个合法 JSON/YAML 资产，重新扫描后无需代码修改即可使用。

## 7. 理论口径与默认值

| 项目 | 统一约定 |
| --- | --- |
| 内存单位 | 内部按 byte；容量显示 MiB/GiB，可切换十进制单位 |
| 算力/带宽 | TFLOPS/TOPS、TB/s 使用十进制；显示精度与位宽 |
| 时间 | 内部统一单位，展示可选 ms/us，导入时显式换算 |
| 工作负载 | 明确 batch、prefill query tokens、历史长度、输出步数、chunk；初期默认等长请求 |
| 输入不完整 | 必填项缺失则相关结果不可用，不默认补零 |
| 参数优先级 | 项目默认 → 资产/模板值 → 方案或节点覆盖；界面可追踪实际来源 |
| 效率 | 峰值乘效率，或直接使用用户有效能力，二者不能隐式重复折减 |
| 权重共享 | 同一设备上的真实共享只算一份；跨设备副本单独计算 |
| 流量 | 逻辑读写、估算 HBM、通信 payload 分栏，避免口径混用 |
| 汇总 | 区分设备局部、设备组合计和有效模型成本 |
| 测量 | 与阶段、范围、设备、次数和区间绑定，无法匹配则不计算相关指标 |

公式仅使用受控表达式：四则运算、比较/条件、求和、min/max、ceil/floor 等。禁止任意代码执行；限制循环与扫描规模，并报告公式错误，不将错误值作为零继续汇总。

## 8. Profiling 与外部 Agent

### 8.1 接入层次

1. 基础版本支持手工输入和统一 CSV/JSON 测量记录。
2. 后续针对选定的 Chrome Trace/算子 CSV 格式提供有限解析器，先导入事件，再由用户确认模块映射。
3. 复杂文件由外部 Agent 或用户脚本转换为统一记录。产品无需采集端，也不要求连接在线 Agent。

### 8.2 统一测量记录

记录至少包含目标节点/模块或待映射事件名、阶段、设备范围、时间及单位、统计方式、调用次数、区间/step 说明。可选字段包含原始事件 ID、来源文件、实际 bytes、映射依据和置信说明。

导入时先展示预览、匹配、歧义和未匹配项，用户确认后应用。未知测量区间不能由 Agent 自动编造；不允许从模型总时间反推并标注子模块为实测。

## 9. 非功能需求

- 本地优先；基础分析和资产保存不依赖联网。
- 单用户、单工作进程优先；不做多人编辑和分布式一致性。
- 资产读取单文件失败不应阻止其他合法资产加载；错误可定位到文件和字段。
- 重复层按需展开，长时间扫描可取消；大运算不阻塞编辑。
- 不设未经样本验证的性能数字承诺；使用代表模型和最大预计展开规模记录基线。
- 定义与计算逻辑分离，资产具备格式版本，后续可迁移。
- 所有结果保留假设与覆盖来源；导出项目包含复算需要的信息。

## 10. 技术方向与复杂度预算

- 产品代码统一使用 TypeScript（严格模式），运行时固定 Node.js 24 LTS 系列；界面采用 React + Vite，包管理采用 npm workspaces。
- 强类型契约以 Zod 4 Schema 为单一来源，推导 TypeScript 类型并导出 JSON Schema Draft 2020-12；正式资产、项目、API 和测量记录使用共享契约。
- JSON/YAML 解析后先结构校验，再进行引用、图、单位和公式等语义校验；不完整草稿不进入计算。
- 核心结构明确分离分层计算图、张量、存储对象、持久状态、逻辑分布、执行计划与分项成本，具体字段与版本规则见技术规范。
- 使用一个轻量本地 Node.js 文件服务读写资产和项目；它仅负责本地文件能力，不承担采集或集群执行。
- 文件系统是持久化事实来源；浏览器存储仅作恢复草稿/缓存。纯浏览器下载不满足自动持久化要求。
- 不引入数据库、任务队列、框架插件系统或完整编译器。
- 计算核心维护一张分层计算图和必要的状态引用，通过视图与分析过程派生结果。
- 对称设备采用代表设备组简化计算；不同分片或不均衡可展开或显式覆盖，不要求第一版枚举大集群全部 rank。
- 通用图/公式模型无法表达时，可先用自定义模块成本公式降级。
